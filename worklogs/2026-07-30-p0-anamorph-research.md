### Custom discrete parameter classes (RawChoice/RawBool/RawInt)
Discrete params are NOT stock AudioParameterBool/Choice/Int. Minimal `RangedAudioParameter` subclasses `RawChoice`, `RawBool`, `RawInt` keep the EXACT raw normalised value in getValue() (atomic<float> normValue) instead of snapping, because pluginval's 'Plugin state restoration' sets a raw normalised value and expects getValue() back within 0.1 — stock discrete classes snap and make getValue()/setValue() private. Host text and DSP still see the snapped value (getText snaps; getRawParameterValue = convertFrom0to1(getValue())). RawBool takes an `automatable` ctor flag (used only by advancedMode). Discrete indices are read in toEngine with `juce::roundToInt`, not a truncating cast, because exact-raw getValue can denormalise a hair below the integer (e.g. 1.9999).

### NormalisableRange choices and skew
Three range styles: (1) plain linear with fine step, e.g. drive {0..24 dB, 0.01}, width/mbWidth {0..2, 0.001}, mix/amount {0..1, 0.001}, balances {-1..1, 0.001}, outputGain {-24..24, 0.01}; (2) one JUCE skew: chorusRate NormalisableRange{0.05, 5.0, 0.001, skew 0.4}; (3) custom lambda ranges: `logFreqRange(lo,hi)` — true octave-even logarithmic mapping (s*pow(e/s,v)) for the three multiband splits (20..20000 Hz), and `logFreqRangeCentred(lo,hi,centre)` — log range warped with a smooth quadratic g(p)=p+a*p*(1-p) so a chosen centre value lands at the slider midpoint (monoMakerFreq 20..500 Hz centred at 120). Both custom ranges include the inverse mapping and a jlimit snap lambda.

### Units / string-from-value and value-from-string lambdas

### Undo model interaction with the parameter system
Undo is custom (APVTS created with nullptr UndoManager), per-A/B-slot, sound-params-only. The processor is an AudioProcessorParameter::Listener on all non-view params: gestures are counted (nested gestures from two-param band moves supported) and exactly one undo step commits after the LAST gesture ends, detected by a 24 Hz editor poll (pollUndoCoalesce) comparing a `soundSignature()` string (5-decimal getValue concat) against the committed baseline. Host automation never opens a gesture so it folds into the baseline WITHOUT an undo step (deliberately not undoable). View params get a separate ViewGenWatcher listener that only bumps a generation counter. Undo entries are full StateSets (params + preset name + baseline). Stack cap 128 per slot. undo()/redo() flush pending coalescing first, push the current set to the opposite stack, and call engine.requestDuck() to mask level jumps.

## patterns_to_copy
- Single `pid` namespace of inline constexpr ID strings in one header as the sole source of truth for IDs, exclusion lists (viewParams/isPresetExcluded), layout, and binding — prevents ID drift across presets/A-B/undo (PluginParameters.h:14-88).
- ParameterID { id, kVersion } on every parameter with a documented bump rule for host automation re-scans (PluginParameters.cpp:94-95,150).
- Additive `raw` attribute on each PARAM node + reassertParameters(prefer raw, fall back to value) for bit-exact state round-trip that passes pluginval's 0.1 raw tolerance while staying backward/forward compatible (PluginProcessor.cpp:263-336).
- notifyHost=false restore path (setValue + direct atomic store, no host notification) for setStateInformation vs notifyHost=true for editor-initiated undo/redo/A-B — prevents DAWs treating a state load as an automation write (PluginProcessor.cpp:287-323).
- Host-hidden InternalState ValueTree child for engine-config/view settings (oversampling, window size, meters) with juce::Value GUI binding, atomic DSP mirror, and a latency-recompute callback — the only reliable way to keep non-musical settings out of the host's parameter list (InternalState.h:10-99).
- Structural legacy detection + one-time read migrations kept forever (bare-tree branch, missing-child migration, legacy slot keys, value-fallback) with frozen XML fixtures exercising each path through the real setStateInformation (PluginProcessor.cpp:535-613; tests/fixtures/*.xml).
- Dependency-free clamp helper (AbSlotIndex.h) for any restored index that feeds an array subscript, unit-tested end-to-end with hand-built corrupt blobs (state_tests.cpp:586-597).
- StateSet = params + preset name + baseline signature as the unit of A/B slots and undo entries, so name + dirty-star travel with every snapshot (PluginProcessor.h:108-121).
- Key=value parameter-registry snapshot fixture freezing IDs, order, names, flags, defaults, functional range probes (den0..den100) and per-step choice text, with numeric-tolerance comparison and an explicit --write-snapshot regeneration gate tied to ADR policy (state_tests.cpp:154-272).
- save->load->save byte-identical assertion as the round-trip fixed-point test — catches lossy or reordered fields cheaply (state_tests.cpp:429-434).
- Two-tier exclusion model: viewParams (out of A/B+undo+presets, in session) vs isPresetExcluded (adds transient/monitor params like the solo mask, reset-on-load) with applyStatePreservingView capturing view values around every snapshot apply (PluginParameters.h:66-88; PluginProcessor.cpp:246-261).
- Preset files store snapped denormalised values only (snap-equivalence contract) while host sessions are raw-exact — two explicitly different fidelity contracts, both tested (state_tests.cpp:687-705).
- Gesture-gated undo coalescing with generation-counter signature caching, preset-load undo bracketing hooks, and host-automation folded silently into the baseline (PluginProcessor.cpp:338-421).

## anabasis_notes
- Naming: Anabasis needs its own root/child/type names (AnamorphRoot, ANAMORPH, ANAMORPH_INTERNAL, .anamorph suffix, RollyTech/Anamorph preset path are product-specific); decide the Anabasis equivalents in DESIGN.md before any serialization code exists.
- Schema version: Anamorph has NO explicit version field and relies on structural detection accreted over 0.2->0.8.x. Greenfield Anabasis can write an explicit schema-version property on the root from v1 and still keep the structural-tolerance read rules — this deviation should be an ADR, since it diverges from the inherited pattern.
- Reported latency: Anamorph's only latency-changing hidden setting is oversampling (InternalState callback -> updateLatency). A loudness maximizer's lookahead/true-peak limiter latency likely depends on ordinary automatable parameters too — decide which parameters may change PDC and reuse the addParameterListener + predictLatency pattern (PluginProcessor.cpp:16-20,95-98); this touches the Anabasis hard-stop 'reported-latency change' gate.
- Simple/Advanced macro-layer: Anabasis' brief adds a Simple/Advanced macro-layer CONTRACT (MODE_AND_ADAPTATION_POLICY) that Anamorph does not have — Anamorph's advancedMode only gates which params reach the engine snapshot (toEngine skip pattern). Whether Anabasis macros write through to underlying params (affecting serialization, A/B, undo) is a design decision Anamorph cannot answer.
- Preset exclusion set must be re-derived per product: Anamorph excludes bypass (view), mbSolo (monitor transient), advancedMode (layout). Anabasis analogues (e.g. bypass, delta/audition monitoring, gain-match, dither/output-format settings, loudness-target display state) need their own tier assignment; copy the two-tier mechanism, not the list.
- InternalState field set is product-specific: oversampling/uiScale/scopePersist/meters/tooltips/animations are Anamorph's. Anabasis must decide which engine-config settings are host-hidden (e.g. oversampling for the limiter, true-peak detection mode?) vs automatable — anything affecting rendered audio that lives host-hidden cannot be automated, which matters more for a mastering limiter (offline-render reproducibility).
- A/B match-gain memory (abMatchGain) is runtime-only in Anamorph and NOT serialized; for a loudness maximizer, loudness-matched A/B is a core workflow — decide whether per-slot match gain must survive session reload (a deliberate difference from Anamorph if so).

## anabasis_notes
- Anamorph has NO discrete Learn phase: 'Learn / Auto Gain' there is a continuously-running Level Match toggle plus an Apply Gain commit button. Anabasis §5.2's Learn ('play a passage, analyse it, fix the internal reference targets') is a start/analyse/finish interaction that does not exist in Anamorph — 'consistency' can only mean reusing the Match/Apply grammar (engage = continuous, gesture-wrapped Apply = commit-and-disengage, live dB readout at 24 Hz, ducked engage/disengage), and Anabasis must design the start trigger, running indication, and end condition itself.
- Anamorph's Apply writes ONE parameter (Output Gain override, clamped to the param range, then disengages Match). If Anabasis Learn writes multiple reference targets, it must wrap all writes in gestures and/or a single undo bracket (mirror commitPresetSwitchUndoStep) so Learn is one undoable step — Anamorph has no multi-param commit precedent.
- Level Match's semantic is 'match wet loudness DOWN/UP to dry' and it REPLACES Output Gain while engaged. A loudness maximizer intentionally raises loudness, so Anabasis must decide whether its Learn output feeds internal reference targets rather than the output stage — copying the replace-Output-Gain behavior would fight the product's purpose.
- Anamorph factory presets are compiled-in override tables, not asset files. Anabasis must decide (ADR per CLAUDE.md cross-repo rule) whether to reuse that pattern, and pick its own extension (.anamorph → e.g. .anabasis) and folder (RollyTech/Anabasis/Presets).
- The preset exclusion list is product-specific: Anamorph excludes bypass/mbSolo/advancedMode. Anabasis needs its own list — notably whether the Simple/Advanced macro-layer state (MODE_AND_ADAPTATION_POLICY, a hard-stop contract) travels with presets/A-B the way Anamorph's advancedMode travels with A/B but not presets.
- The forced-duck dry-fill only engages when the swap keeps reported latency (predictLatency == latched latency). A mastering maximizer with lookahead/oversampling latency will cross latency on more preset/A-B swaps than a widener, so Anabasis should expect duck-to-silence more often and decide whether that is acceptable during mastering playback, or design a different masking strategy.
- Per-A/B-slot auxiliary memory (abMatchGain + injectMatchGainDb consumed at the silent bottom) is the pattern Anabasis needs for any per-slot Learn state (e.g. learned reference targets per slot); Anamorph stores it processor-side, NOT in the APVTS, and does not serialize it with the session (abMatchGain is not in getStateInformation) — Anabasis must decide whether learned targets persist in session state.
- No parameter-lock mechanism exists in Anamorph. If Anabasis wants locks (e.g. lock the output ceiling across preset loads), that is new design with no family precedent — the closest Anamorph idiom is the static exclusion list, which is compile-time, not user-facing.
- Anamorph's Level Match never runs during a 'measurement pass' UI: the only running feedback is a right-aligned 11pt dB label polled at 24 Hz with bitwise change-gating. If Anabasis Learn needs progress (integrated LUFS over a passage), that display machinery must be new; copy only the atomic-publish + change-gated re-format idiom.
- Session-state schema decisions to mirror deliberately: A/B slots serialized as XML strings with name+baseline per slot, active index clamped on restore, undo history never serialized, preset name/baseline as root properties. Anabasis's serialization registry should adopt the same shape (its brief inherits Anamorph's engineering standard) but with its own root tag and internal-state child name.

### Animation architecture — FrameClock
FrameClock is a header-only adaptive refresh driver replacing fixed 60 Hz juce::Timers for the visualizers. It wraps juce::VBlankAttachment (follows the component across monitors), measures vblank cadence with a 0.125 EMA over deltas in (0.5 ms, 50 ms), and divides to an EVEN cadence <= ~125 Hz: run every ceil(rate/126)-th vblank (60->60, 120->120, 144->72, 240->120). A sustained rate INCREASE (delta < 0.75*EMA, confirmed by a second consecutive short delta) snaps the estimate to re-cap within ~2 frames; unmeasurable cadence falls back to ~60 Hz wall-clock pacing. Callbacks receive real elapsed dt clamped to 50 ms, on the message thread. A companion frameCoeff(c60, dt) = 1 - pow(1-c60, dt*60) converts legacy per-tick 60 Hz lerp coefficients to frame-rate-independent form (used e.g. for the correlation pointer glide 0.030 relaxed / 0.165 active).

### Parameter snapshot pattern (APVTS -> audio thread)
No message queue, no FIFO of parameter changes. ParamPointers caches std::atomic<float>* from apvts.getRawParameterValue() once at construction (bind()); every processBlock the wrapper rebuilds a full plain-old-data EngineParameters snapshot via params.toEngine(internal.oversampleIndex()) with relaxed atomic loads, then calls engine.setParameters(e) followed by engine.process(buffer). EngineParameters is a POD struct of enums/bools/floats grouped by chain stage; the engine knows nothing about JUCE/APVTS/parameter IDs and could be reused under AU/AAX wrappers unchanged. Discrete choice indices are read with juce::roundToInt, not a truncating (int) cast, because the exact-raw getValue() can denormalise a legal choice a hair below its integer (e.g. 1.9999). Host-hidden params (oversampling) bypass APVTS entirely: InternalState carries std::atomic<int> osAtomic read relaxed on the audio thread. Advanced/Simple gating happens at snapshot-build time: when advancedMode<=0.5 the Advanced-only fields are simply left at EngineParameters' neutral member-initialiser defaults while the knob values stay in the tree.

### Click-free discrete switching: asymmetric raised-cosine duck state machine
Discrete changes (algorithm, routing, M/S, band count, autoGainMatch toggle, OS-path engagement) are applied only at the silent bottom of a raised-cosine output duck: SwitchState {Normal, FadeOut, FadeIn}, phase stepped per sample, gain = 0.5 - 0.5*cos(pi*phase) (zero slope at both seams). ### LoudnessMatch: measurement chain and placement
K-weighted (ITU-R BS.1770) dual-signal loudness matcher, modeled on Soundtheory Kraftur Match/Apply. Per channel per signal: high-shelf 'head' biquad (f0=1681.974450955533 Hz, G=3.999843853973347 dB, Q=0.7071752369554196) into RLB high-pass (f0=38.13547087602444 Hz, Q=0.5003270373238773), all double-precision transposed-direct-form-II biquads. Mean-square integrated by a single-pole ~400 ms window (tau=0.4, momentary-loudness style). matchGainDb = LUFS(dry) - LUFS(wet) with the -0.691 BS.1770 offset in both terms (cancels), clamped to +/-24 dB, published via std::atomic<float> relaxed. Placement: measured post-Mono-Maker (the real processed output) but PRE Output Gain/Balance, so the published gain is 'the trim that would restore dry loudness'. The dry reference is NOT the raw input: it is loudnessRefScratch = the delay-aligned phase-matched reconstruction A(dry) pushed through the same crossovers at unit width, so the Multiband's allpass-reconstruction magnitude ripple cancels and Measure reads ~0 at identity settings; falls back to the delay-aligned clean input when Multiband is off. When engaged, the smoothed match gain REPLACES Output Gain (g = autoGainMatch ? matchGain : outGain), applied through the slow 120 ms matchGainSmooth. 'Apply' workflow: GUI reads getMatchGainDb(), writes it into the outputGain parameter as a fixed value via gesture-bracketed setValueNotifyingHost, then disengages Match — so exports are deterministic, not adaptive.

### LoudnessMatch: how it avoids becoming an AGC (MEASURE/PREDICT split + freeze rules)
Explicitly 'deliberately NOT a continuously-adapting export-time AGC'. Four mechanisms: (1) MEASURE freeze on silence — when both K-weighted mean-squares fall below 1e-6 (~-60 dBFS) the displayed gain HOLDS its last trusted value, never drifting toward 0. (2) Asymmetric two-rate glide on the displayed value: |target - displayed| > 2 dB uses coeffFast (tau 60 ms), else coeffSlow (tau 0.9 s) — fast convergence on real changes, near-static once settled. (3) PREDICT: an ABSOLUTE (stateless, non-accumulating) feed-forward estimate of the boost as a pure function of Drive and Mix — estDriveBoostDb = min(14, 0.5*blend*20*log10(g/tanh(g))) scaled through the wet/dry ratio (1-m)+m*B — that only ever LOWERS the published gain, and only when the estimate RISES (predictDelta < 0 applies displayedGainDb = min(displayed, predicted)); a falling estimate never raises the gain (measurement eases it back), which kills ratcheting and path dependence. This pre-duck makes the first block out of a pause safe even if the host never ran the plugin while paused. (4) softReset() re-arms filters + integrators WITHOUT zeroing displayedGainDb/prevPredictedGainDb, so an A/B re-converges from the current value instead of snapping; softReset is called only when processingDiffers (never on Match/Bypass toggles). Supporting engine-side idioms: prevInputSilent silence->audio edge latch snaps matchGainSmooth to the (pre-ducked) target on the first audible block (click-free because the previous block was silent); per-A/B-slot match memory injected through std::atomic<float> matchInject consumed at the silent duck bottom.

## anabasis_notes
- Latency model must generalise beyond Anamorph's single-source OS-only model: Anabasis has lookahead (0.5-10 ms, brief line 95), possible linear-phase OS mode, and dither/limiter stages, so predictLatency must SUM contributions and the reported value changes with a continuous parameter (lookahead) — Anamorph's premise 'latency != 0 only when OS engaged' (AnamorphEngine.cpp:431-454) and the dry/bypass ring sizing maxLat+maxBlock+1 (AnamorphEngine.cpp:84-98) need a larger bound (max lookahead + max OS latency). The latched-at-silent-bottom rule for latency changes (osEngaged, #3) is worth keeping, but a lookahead DRAG cannot duck per tick; Anabasis must decide whether lookahead is quantised/duck-switched or continuously variable with internal max-lookahead padding (constant reported latency). LATENCY_MODEL.md:51-56 makes any reported-latency semantics an ADR-level decision.
- LoudnessMatch's dry/wet comparison inverts for a maximizer: Anamorph compensates a roughly loudness-neutral widener (gain clamp +/-24 dB, symmetric); Anabasis's wet is ALWAYS louder, so the compensation gain is essentially always negative and its PREDICT analogue should be driven by Gain/Threshold + Ceiling (the deterministic gain lift of a limiter is far more predictable than tanh drive — estBoostDb's Drive/Mix formula at LoudnessMatch.cpp:77-98 is replaced by input-gain minus expected GR). The floor-only 'predict may only lower, never raise' rule and the silence-freeze translate directly.
- True-peak/LUFS metering per BS.1770-4 (brief lines 99, 207) needs gated integrated loudness and >=4x true-peak detection — Anamorph's LoudnessMatch is momentary-only (400 ms one-pole, LoudnessMatch.cpp:56-58) and ungated; the K-weighting biquads and the atomic-publish pattern are reusable, but the integrator, the gating blocks (400 ms / 75% overlap, -70 LUFS absolute + -10 LU relative gates) and a true-peak upsampler are new modules. Anamorph's OS wraps only the nonlinear region; Anabasis's OS must ALSO serve true-peak detection (brief line 628), so the oversampler topology (one shared wrap vs a separate detection upsampler) is a P0 decision with no Anamorph precedent.
- Delta monitoring (brief line 75) has no Anamorph equivalent, but the bypass ring gives the recipe: delta = delay-aligned raw input minus processed output, using exactly the bypassDelayBuffer alignment machinery (AnamorphEngine.cpp:777-846); it should be a post-everything monitor stage like SoloMonitor (never affecting the processing path) with its own crossfade so toggling is click-free.
- Anamorph reports latency==0 in the common case, so its forced-duck dry-fill could gate on 'latency unchanged' (AnamorphEngine.cpp:290-307); Anabasis always has nonzero lookahead latency, which actually makes the dry-fill gate EASIER (latency rarely changes) but means true-bypass null tests must account for constant PDC, and the bypass ring is always exercised (Anamorph's write-only fast path at :829-845 will rarely be the hot path if loudness-compensated monitoring keeps the crossfade armed).
- Anabasis has a Simple/Advanced macro-layer contract (its CLAUDE.md hard-stops) — Anamorph gates Advanced fields at snapshot-build time in toEngine (PluginParameters.cpp:352-386, neutral defaults when Simple). Anabasis must decide whether the one-knob Loudness macro maps onto underlying Advanced params (values visible/round-trippable) or gates like Anamorph; the Anamorph approach means Simple mode literally builds a different snapshot, which interacts with the sameParameters bitwise gate and undo signatures.
- The engine-side no-AGC freeze threshold (~-60 dBFS mean square, LoudnessMatch.cpp:127-128, AnamorphEngine.cpp:1159) may be too high for mastering material with wide dynamics (quiet classical passages would freeze compensation); Anabasis should pick its silence gate against the BS.1770 -70 LUFS absolute gate rather than copying 1e-6.
- ScopedNoDenormals covers FTZ/DAZ only inside processBlock; Anamorph's modules rely on it for exact-zero settling (HaasProcessor.cpp:51). Anabasis's brief demands 'denormal protection (FTZ/DAZ)' explicitly (brief line 49) — same mechanism suffices, but ADAA state and linear-phase FIR tails (if chosen) should be audited for denormal-prone feedback paths the same way.
- Anamorph has zero worker threads (THREAD_MODEL.md:13, FFT on GUI thread); Anabasis's linear-phase mode and 16x offline oversampling may not fit that constraint — a P0 decision (background FIR design thread vs precomputed kernels) with no Anamorph precedent.
- GR history / PLR display (brief line 207) needs a time-series channel to the GUI; ScopeBuffer's SPSC-ring-with-single-release-store is the right primitive to copy (per-block GR values instead of per-sample audio), rather than the LevelMeters instantaneous-atomics pattern.
